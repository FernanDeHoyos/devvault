# DevVault Core Concepts

## Qué es un Workspace?

Workspace significa literalmente “espacio de trabajo”. En tecnología, suele referirse a un entorno digital donde se organizan archivos, herramientas, personas y proyectos para trabajar de forma individual o colaborativa.

Por ejemplo, Google Workspace reúne servicios como Gmail, Drive, Documentos, Hojas de cálculo, Meet y Calendar en una misma plataforma para comunicarse, crear archivos y colaborar en línea.

En otros programas, un workspace puede ser simplemente:

- Una carpeta o proyecto con sus archivos relacionados.

- Un espacio compartido para un equipo.

- Un entorno de trabajo dentro de una aplicación.

- Un conjunto de configuraciones, ventanas o recursos guardados.

En resumen: un workspace es como un escritorio digital organizado, pero el significado exacto depende de la aplicación donde aparezca.

## ¿Qué es un Proyecto?

Un proyecto es un conjunto de actividades planificadas y coordinadas para alcanzar un objetivo específico. Normalmente tiene un inicio y un final, utiliza recursos —como tiempo, dinero o personas— y busca crear un producto, servicio o resultado concreto.

Por ejemplo, organizar una campaña de limpieza, desarrollar una aplicación o construir una casa son proyectos.

### Elementos de un proyecto
- Un objetivo claro.
- Actividades o tareas.
- Un plazo definido.
- Recursos disponibles.
- Personas responsables.
- Un resultado esperado.

La diferencia entre un proyecto y una actividad rutinaria es que el proyecto es temporal y único, mientras que una operación rutinaria se repite continuamente.

## Qué es un Servicio?

Un servicio es una actividad o conjunto de actividades que una persona, empresa u organización realiza para satisfacer una necesidad de otra persona. A diferencia de un producto, normalmente no es algo físico que puedas tocar o guardar.

### Ejemplos
- Un médico ofrece atención sanitaria.
- Un profesor ofrece enseñanza.
- Un banco ofrece servicios financieros.
- Una empresa de internet ofrece conexión.
- Un técnico ofrece reparación de equipos.

En resumen, un servicio es algo que alguien hace para ayudarte o aportarte valor, generalmente a cambio de un pago.

### ¿Qué diferencia hay entre un Servicio y un Recurso Compartido?

Un servicio es una función o actividad que se ofrece para satisfacer una necesidad. Un recurso compartido es un archivo, carpeta, dispositivo o aplicación que se pone a disposición de varias personas o equipos, normalmente mediante una red.

| Concepto | Qué es| Ejemplo|
| ---------------------------------------------------------| ----------------------------------- | ---------------------------------------------------------- |
| Servicio | Algo que un sistema, persona o empresa hace para proporcionar una función | Servicio de correo electrónico, impresión o almacenamiento |
| Recurso compartido | Algo que varios usuarios pueden utilizar o consultar                      | Carpeta compartida, impresora de red o disco compartido    |


### Diferencia principal
- El servicio es la función que se presta.
- El recurso compartido es el elemento que se comparte para permitir el acceso o uso.

Ejemplo: en una red, la impresión en red es el servicio; la impresora conectada y disponible para varios usuarios es el recurso compartido. A menudo, un servicio permite acceder o administrar recursos compartidos.

## Cuándo un proyecto está "Running" o "Healthy"?

Un proyecto está “Running” cuando se encuentra en ejecución: se ha iniciado y sus tareas, procesos o actividades están desarrollándose. No significa necesariamente que todo vaya bien, solo que el proyecto está activo.

Un proyecto está “Healthy” cuando, además de estar activo, funciona correctamente y avanza según lo previsto, sin problemas importantes que amenacen sus objetivos. Normalmente se revisan aspectos como el plazo, el presupuesto, el alcance, la calidad y los riesgos.

| Estado  | Significado                                               |
| ------- | --------------------------------------------------------- |
| Running | El proyecto está iniciado y ejecutándose.                 |
| Healthy | El proyecto está en buen estado y progresa adecuadamente. |

Ejemplo: un proyecto puede estar Running pero no Healthy si está activo, aunque tenga retrasos graves, errores o falta de recursos. Lo ideal es que esté Running + Healthy: en ejecución y funcionando bien.

## ¿Qué significa "escanear" un proyecto?

**Escanear un proyecto** significa realizar una revisión automática o detallada de sus componentes para conocer su estado y detectar posibles problemas.

Según la herramienta, el escaneo puede revisar:

- La configuración del proyecto.
- Sus archivos, tareas o recursos.
- Errores, incompatibilidades o elementos faltantes.
- Vulnerabilidades de seguridad.
- Riesgos, retrasos o problemas de calidad.
- Si cumple determinadas reglas o requisitos.

El resultado suele ser un informe con advertencias, errores o recomendaciones. En resumen, escanear un proyecto es como hacerle una **revisión o diagnóstico** antes de continuar.

**Ejemplo:** si escaneas un proyecto de software, la herramienta puede comprobar que no tenga vulnerabilidades, dependencias desactualizadas o errores de configuración.
